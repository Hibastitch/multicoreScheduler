# superseded/ — invalid results, kept only for provenance. Never cite these.

Every reason below is cited from `docs/NOTEBOOK.md`'s dated ledger — follow the reference to see the original finding.

- **`results.csv`, `results_migration_penalty2ms.csv`** — generated entirely under `legacy_ema` with the shared-RNG bug present (Fix 3d, `docs/NOTEBOOK.md` "Task 6, Step 3" entry, 2026-09-27): baseline and burst-aware secretly saw *different* task streams for "the same seed," invalidating every paired comparison. Also predate the 2026-09-27i default-configuration flip.
- **`task1_followup.py`, `task1_heavytail_check.py`, `results_task1_heavytail.csv`** — Task 1's original `heavy_tail`/high check, explicitly marked INVALID for paired comparison (`docs/NOTEBOOK.md`, "Point 5," 2026-09-27c-area entry): the "tail-clipping" pattern it found was most likely comparing two *different* randomly-generated workloads under the same nominal seed (the pre-Fix-3d RNG bug), not a real scheduling effect.
- **`task5_stacked_burst.py`, `results_task5_stacked_burst.csv`, `task5_full_output.txt`** — the original `stacked_burst` hypothesis test, run against an older, less faithful baseline missing some combination of Fix 3d / newidle-transition / Fix A / Fix B / Fix C (`docs/NOTEBOOK.md`, "Task 6, Step 3" entry, 2026-09-27): explicitly superseded by that full A+B+C re-run.
- **`task6_step3_full_rerun.py`, `results_task6_step3_full_rerun.csv`, `task6_step3_output.txt`** — a legitimate full A+B+C re-run for its time, but predates the detector threshold calibration and the `burst_resets_timer`/final-config defaults; superseded as the "final" numbers by `final_results/2_confirmation/`'s later run on fresh seeds.
- **`task6_burst_size_sweep.py`, `results_task6_burst_size_sweep.csv`, `task6_burst_size_sweep.png`** — a real bug, not just an outdated baseline: the fixed `burst_duration=8` combined with `arrival_rate_during_burst=1.5` capped ACTUAL emitted tasks per burst at 13 regardless of requested `burst_size` (confirmed directly: `requested=16` → `actual=13`, `requested=64` → `actual=13`). Sizes 16-64 in this sweep silently tested the IDENTICAL effective workload — their byte-identical numbers are an artifact of the cap, not a real saturation finding. Superseded by `development/sweeps_precalibration/task6_sweeps_v2.py`, which fixes `burst_duration = burst_size / arrival_rate_during_burst`.
- **`task6_plot_sweep.py`, `task6_sweep_output.txt`** — the plot and captured output of the buggy sweep above; invalid for the same reason.
- **`task6_verify_timer_attempts.py`** — v1 of the attempt-trace: its domain/checker identification matched `is_designated_checker()` calls by TIMESTAMP alone, so it silently picked whichever domain happened to be checked first in iteration order (core 0 / n0-pair0, every single time) instead of the burst's own actual domain (`docs/NOTEBOOK.md`, "Correction (2026-09-27c)"). Every result it produced was comparing the WRONG domain. Superseded by `development/low_intensity_reversal/task6_verify_timer_attempts_v2.py`, which identifies the domain/checker directly from the burst-tagged `_balance_domain()` call.
- **`Experiment.py`** — early experiment harness, not used by the final pipeline (`final_results/` scripts call `Main.run_simulation` directly). Kept for history, not for an invalid-result reason like everything else in this file — several later modules' comments (`paired_compare.py`, `Topology.py`, `WorkloadGenerator.py`, `development/sweeps_precalibration/stress_test_bursty.py`) still cite its original seed scheme (`1000*profile_id + 100*intensity_id + rep`) for context.
